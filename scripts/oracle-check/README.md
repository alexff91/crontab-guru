# Сверка с чужими реализациями cron

Ошибка, из-за которой появилась эта папка: «следующие запуски» считались
пересечением дня месяца и дня недели, хотя cron берёт объединение. Ошибка
прожила долго, потому что проверялась тем же пониманием, из которого возникла.
Поэтому проверка тут устроена так, что наш код с собой не сверяется.

## Как запустить

```bash
bash scripts/oracle-check/run.sh
```

Скрипт соберёт `src/utils/cron-parser.ts`, поставит рядом (не в зависимости
приложения) `cron-parser` и `croner`, при необходимости заведёт venv с
`croniter` и сравнит ответы на ~650 выражениях × 7 стартовых моментах.

## Что означает результат

Голосуют три чужие библиотеки: **croniter** (Python), **cron-parser** (JS),
**croner** (JS). Библиотека, которая на выражении ругнулась, не голосует.

* `allAgree` — все ответившие сошлись с нами;
* `oneOracleDiffers` — кто-то один разошёлся, а мы в большинстве;
* `weAreTheOutlier` — **это провал**, скрипт вернёт код 1.

Единственный ответ — не проверка: важна доля и то, что мы нигде не в
меньшинстве.

## Известные расхождения (проверено 2026-08-22)

| выражение | кто отличается | суть |
|---|---|---|
| `1-1`, `10-10`, `11-11/4` — диапазон из одного значения | croniter 6.2.4 | раскрывает такой диапазон как `*`, то есть «каждую минуту/каждый день». `cron-parser` и `croner` согласны с нами: это одно значение |
| `23/4`, `14/6` — старт со шагом за границей поля | croniter 6.2.4 | теряет старт и считает как `*/шаг` |
| `0 0 1 * 1` — оба поля дня заданы | croner 10 | отдаёт только понедельники, теряя первые числа; croniter и cron-parser берут объединение, как crontab(5) |
| `5-1` — обратный диапазон | — | мы отвергаем, как cron-parser и croner; croniter молча раскрывает через край |
| `L`, `W`, `#` | — | мы отвергаем с объяснением: это расширения Quartz, обычный cron их не знает. croniter и cron-parser их понимают |

Отдельный случай — «баг vixie cron». Если одно из полей дня начинается со
звёздочки (`*/2`), настоящие демоны vixie/ISC считают его незаданным и берут
пересечение, а не объединение. croniter держит для этого флаг
`implement_cron_bug`, см. https://crontab.guru/cron-bug.html. По умолчанию все
три библиотеки (и мы) берут объединение, но интерфейс в таком случае пишет
предупреждение, а не делает вид, что ответ единственно возможный.

## Файлы

* `cases.cjs` — генерирует выражения и наши ответы (`ours.json`);
* `croniter-out.py` — ответы croniter (`croniter-out.json`);
* `compare.cjs` — голосование, код возврата 1 при провале;
* `verify-test-expectations.cjs` — вытаскивает из файла тестов все ожидания
  вида `runs('...', n, '...')` и проверяет их чужими библиотеками. Нужен, чтобы
  в тесты не попали числа, придуманные автором.
